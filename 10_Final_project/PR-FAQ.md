## 3. Problem — 해결한 문제

### 문제 1. 프린터의 정상 작동과 실제 출력물의 정상 상태는 다르다

FDM 프린터는 G-code의 명령에 따라 노즐을 이동시키고 재료를 압출하지만, 출력물이 실제로 정상적인 형상으로 만들어졌는지는 직접 확인하지 못한다.

특히 베드 접착 실패, 서포트 파손 및 오버행 처짐이 발생해도 프린터는 남아 있는 명령을 계속 실행할 수 있다.

이러한 이상을 늦게 발견하면 출력 시간과 필라멘트가 낭비되고, 시제품 제작 일정에도 영향을 줄 수 있다.

### 문제 2. 복잡한 출력 형상은 단순 영상 변화만으로 판단하기 어렵다

일반적인 영상 차분이나 객체 추적 알고리즘은 출력물의 이동을 감지할 수 있다.

하지만 정상적인 FDM 출력도 레이어가 쌓이면서 형상이 지속적으로 변한다. Tree Support, 인필, 브리징 등은 처음부터 불규칙한 구조를 가지고 있어 단순한 움직임이나 외곽 변화만으로 불량을 구분하기 어렵다.

따라서 다양한 정상 적층 상태의 시각적 특징을 학습하고, 새로운 영상에서 비정상적인 특징이 나타나는 위치를 찾아내는 접근이 필요하다.

### 문제 3. 기존 실패 감지 서비스와 구별되는 기술적 가치가 필요하다

Obico와 OctoEverywhere 등은 이미 AI 기반 출력 실패 감지 기능을 제공한다.[^1][^2]

따라서 일반적인 Spaghetti Detection을 다시 구현하는 것만으로는 차별성이 부족하다.

PrintStop은 **정상 출력 상태를 학습한 딥러닝 모델과 G-code의 적층 단계 정보를 결합**하는 방법에 초점을 맞춘다.

이 조합이 영상만 사용하는 모델보다 실제 이상을 더 정확하게 구분하는지는 비교 실험으로 확인한다.

## 4. Solution — 제공한 솔루션

### 솔루션 1. 정상적인 출력 상태를 딥러닝으로 학습한다

PrintStop은 정상적으로 출력되는 본체와 서포트의 이미지를 수집한다.

사전학습된 CNN을 이용해 이미지의 지역적 특징을 추출하고, PatchCore 방식으로 정상 특징을 저장한다.[^3]

새로운 출력 영상이 입력되면 정상 특징과 비교해 이상 점수를 계산하고, 비정상적 특징이 나타난 위치를 Heatmap으로 표시한다.

초기에는 정상 이미지로 기준 특징을 구성하는 방식이므로, 다양한 실패 이미지를 대량으로 학습해야 하는 부담을 줄일 수 있다. 다만 실제 성능 평가에는 반드시 실패 영상이 필요하다.

### 솔루션 2. G-code로 출력 단계에 맞는 정상 상태를 비교한다

정상 출력도 적층 단계에 따라 형태가 달라지므로, 모든 레이어의 이미지를 하나의 기준으로 비교하면 오경보가 발생할 수 있다.

PrintStop은 G-code에서 레이어와 출력 경로를 추출하고, 가능한 경우 서포트·본체·서포트 인터페이스 등의 출력 단계를 구분한다.

딥러닝 모델이 현재 영상의 특징을 분석할 때 해당 적층 단계와 관련된 정상 이미지 또는 검사 영역을 우선 활용하도록 한다.

즉, **딥러닝은 실제 형상의 정상·이상 특징을 분석하고, G-code는 현재 어떤 구조를 기준으로 비교할지 결정한다.**

### 솔루션 3. 시계열 정보를 활용해 이상 발생 위치와 시점을 제공한다

단일 프레임의 이상 점수만으로 출력 실패를 확정하지 않는다.

이상 점수가 여러 프레임에서 지속되는지, 특정 구조에서 비정상적인 변화가 확대되는지 등을 확인한다.

사용자에게는 이상 점수, 의심 영역 Heatmap, 발생 시점 및 관련 적층 단계 정보를 제공하여 출력 상태를 검토하도록 지원한다.

# Part 3. 외부 고객용 FAQ

## Q1. PrintStop은 정확히 무엇이며, 저에게 어떤 의미가 있나요?

PrintStop은 FDM 3D 프린팅 과정을 딥러닝으로 분석하고, 실제 출력물의 비정상적인 형상이나 움직임이 관찰되면 해당 영역과 시점을 알려주는 프로그램이다.

주요 고객은 개인 시제품 제작자, 대학 연구실 및 소규모 제작실이다.

사용자는 전체 영상을 반복적으로 확인하는 대신, 시스템이 제시하는 의심 구간을 중심으로 출력 상태를 점검할 수 있다.

## Q2. 기존 방식과 비교해서 무엇이 달라졌나요?

기존 AI 모니터링 서비스도 출력 실패 감지 기능을 제공한다.

PrintStop은 정상적인 적층 상태의 특징을 학습하고, G-code로 현재 출력 단계에 맞는 검사 대상 및 비교 기준을 설정한다.

특히 정상적으로 형성되는 복잡한 서포트 구조와 실제로 파손된 서포트를 구분하는 방향을 연구한다.

**다만 기존 상용 서비스보다 정확하다는 것은 아직 검증된 사실이 아니다.**

## Q3. 언제부터 적용되며, 누가 대상인가요?

연구용 시제품의 공개 목표일은 2026년 11월 30일이다. ⚠️ 팀 계획

초기 대상은 고정 카메라로 촬영할 수 있는 FDM 프린터를 이용하는 개인 제작자와 연구실이다.

범용 상용 제품이 아니라 실제 검증한 프린터·슬라이서 조합을 대상으로 시험한다.

## Q4. 이용하려면 어떤 조건이 필요한가요?

출력 작업의 G-code, 프린터를 촬영할 고정 카메라, 영상 분석용 PC가 필요하다.

딥러닝 모델이 정상적인 출력 상태를 학습할 수 있도록 정상 출력 영상도 확보해야 한다.

특히 G-code의 적층 정보와 영상의 진행 단계가 대응되어야 하며, 출력물이 심하게 가려지는 경우에는 결과의 신뢰성이 낮아질 수 있다.

## Q5. 추가 비용이나 시간이 필요한가요?

기존 PC와 스마트폰을 활용하면 초기 장비 비용을 줄일 수 있다.

다만 카메라 설치, 정상 영상 확보, 모델의 정상 특징 저장, 영상 처리 및 데이터 저장에 시간과 컴퓨팅 자원이 필요하다.

초기 버전은 연구·검증 목적이며 유료 서비스 가격이나 고객의 지불 의사는 아직 확인되지 않았다.

## Q6. 구체적으로 어떻게 사용하나요?

1. G-code를 등록하고 카메라로 출력 과정을 기록한다.
2. 정상 출력 영상으로 구성한 딥러닝 모델이 실제 출력 상태를 분석한다.
3. G-code의 현재 출력 단계에 따라 검사 영역 또는 정상 비교 기준을 선택한다.
4. 이상 점수가 일정 시간 지속되면 관련 영상과 Heatmap을 표시한다.
5. 사용자가 영상을 확인하고 출력 지속 또는 중단 여부를 결정한다.

초기 버전은 녹화 영상 분석을 우선 지원하며, 자동 출력 중단 기능은 포함하지 않는다.

## Q7. 출력 실패를 사전에 예측할 수 있나요?

현재 프로젝트는 실패가 발생하기 전에 미래의 파손을 예측하는 기술이 아니다.

딥러닝은 영상에서 이미 관찰되기 시작한 비정상적인 특징을 감지한다.

예를 들어 서포트의 내부 강도가 낮아졌다는 사실은 일반적인 RGB 영상만으로 알 수 없지만, 구조가 기울어지거나 형태가 변하기 시작하면 그 변화를 분석할 수 있다.

따라서 **'사전 예측'이 아니라 '관찰 가능한 이상 징후의 조기 감지'**를 목표로 한다.

## Q8. 정상적인 출력 형상을 불량으로 잘못 판단할 수 있지 않나요?

가능하다. 이것은 PrintStop의 핵심 기술적 위험이다.

정상 출력물도 레이어가 증가하면서 형상이 바뀌고, Tree Support처럼 불규칙한 구조가 나타난다.

이를 줄이기 위해 출력 단계가 다른 정상 이미지를 수집하고, G-code 정보를 활용해 유사한 적층 단계끼리 비교한다.

또 단일 프레임의 높은 이상 점수만으로 경고하지 않고 시간적 지속성을 확인한다. 오경보가 얼마나 줄어드는지는 실험으로 검증한다.

## Q9. 이미 Obico 같은 제품이 있는데 왜 PrintStop을 사용해야 하나요?

일반적인 실패 감지와 원격 모니터링이 목적이라면 기존 서비스로 충분할 수 있다.

PrintStop의 연구 목적은 **특정 출력물의 적층 정보와 정상 상태 학습을 결합해 서포트와 형상 이상을 분석하는 것**이다.

따라서 기존 서비스와 동일한 기능을 제공한다는 것만으로 제품 가치가 생기는 것은 아니다.

G-code 결합이 오경보 감소, 이상 위치 식별 또는 사용자 검토시간 단축에 기여하는지가 확인되어야 경쟁력을 주장할 수 있다.

## Q10. 사용자 피드백은 어떻게 반영하나요?

사용자는 표시된 이상 구간을 실제 이상, 정상 출력 또는 판단 불가로 평가할 수 있다.

이러한 결과는 모델의 오경보 분석과 정상 데이터 보완에 사용한다.

사용자가 제공한 영상은 동의받은 범위에서 사용하며, 별도 동의 없이 외부 공개하지 않는다.

# Part 4. 내부 이해관계자용 FAQ

## Q11. 왜 지금 이 프로젝트를 해야 하나요?

FDM 출력에서는 베드 이탈, 서포트 파손 및 형상 이상으로 시간과 재료가 낭비될 수 있다.

기존 AI 출력 감지 서비스가 존재하므로, 단순 객체 탐지보다 더 구체적인 기술적 목표가 필요하다.

PrintStop은 **정상 출력의 딥러닝 특징 학습과 G-code의 공정 정보를 결합했을 때 실제 감지 성능이 개선되는가**라는 연구 질문을 설정한다.

PatchCore와 같은 정상 데이터 기반 이상탐지 방법이 이미 개발되어 있어, 이를 FDM 출력의 시간적·공정적 특성에 적용하는 실험이 가능하다.[^3]

## Q12. 프로젝트의 학습목표와 어떻게 연결되나요?

**딥러닝:** 사전학습 CNN을 이용한 특징 추출, 정상 특징 저장, PatchCore 기반 이상 점수 및 Heatmap 생성.

**컴퓨터비전:** 영상 정합, 출력물 영역 추출, 시계열 변화 분석.

**기계공학:** FDM 적층 원리, 서포트 생성, G-code 파싱, 출력물 형상 및 실패 유형 해석.

**시스템 통합:** 딥러닝 분석 결과와 G-code의 적층 단계 정보를 연결하고, 기존 영상 처리 방식과 성능을 비교한다.

## Q13. 예상 ROI와 사업적 효과는 무엇인가요?

현재 PrintStop의 실제 비용 절감 효과는 검증되지 않았다.

경제적 가치는 실패 감지로 출력 중단이 빨라졌을 때 절약되는 재료량과 작업 시간에 따라 평가한다.

```text
잠재적 절감 시간
= 기존 실패 발견 시점 - PrintStop 감지 시점

잠재적 절감 재료량
= 감지 시점 이후 실제로 사용하지 않게 된 재료량

순편익
= 실제 확인된 출력 비용 절감액 - 시스템 운영 비용
```

단, 사용자가 알림을 확인하고 실제로 출력을 중단한 경우에만 절감 효과가 발생한다.

사업화 여부는 기존 서비스 대비 개선 효과와 고객의 지불 의사를 확인한 뒤 판단한다.

## Q17. 프로젝트 중단 또는 축소 기준은 무엇인가요?

### 기준 1. 딥러닝 적용 효과가 없는 경우

실제 평가 데이터에서 딥러닝 기반 이상탐지가 OpenCV Baseline보다 유용한 개선을 보이지 못하면, 딥러닝이 필요한 이유를 입증하지 못한 것으로 판단한다.

이 경우 모델 구조, 정상 데이터의 다양성, 출력 단계별 비교 방법을 분석하고 결과를 공개한다.

### 기준 2. 서포트 실패 데이터가 부족한 경우

실제 서포트 파손에 대한 영상과 정답을 확보하지 못하면 서포트 감지 성능의 정량 평가를 중단한다.

정상 서포트의 특징 학습과 이상 Heatmap의 동작 여부는 시연할 수 있지만, 이를 실제 서포트 파손 검출 성공으로 간주하지 않는다.

### 기준 3. G-code와 영상이 연결되지 않는 경우

동일 출력 작업의 G-code와 영상이 확보되지 않으면 공정 정보 결합 성능을 검증하지 않는다.

이 경우 딥러닝 기반 영상 이상탐지와 G-code 파싱 결과를 별도 기능으로 보고하고, 결합 효과를 입증했다고 주장하지 않는다.

**Exit 전략:** 기술적 한계가 확인되더라도 정상 특징 학습, 영상 이상탐지, G-code 파싱 및 평가 코드 등은 재사용 가능한 연구 결과로 보존한다.

## Q18. 성공을 어떻게 정량적으로 평가하나요?

### 비교 실험 설계

| 실험군 | 입력 | 검증 목적 |
|---|---|---|
| **Baseline A** | OpenCV 기반 프레임 차분·움직임 분석 | 전통적인 비전 알고리즘 성능 |
| **Baseline B** | CNN + PatchCore | 딥러닝 기반 이상 특징 분석 효과 |
| **Proposed** | CNN + PatchCore + G-code | 공정 정보 결합의 추가 효과 |

세 방식은 동일한 평가 데이터에서 비교한다.

딥러닝 학습에 사용한 출력 작업의 프레임이 평가 데이터에 섞이지 않도록 **출력 작업 단위로 데이터셋을 분리**한다.

### Primary KPI

| 지표 | 정의 | 목표 |
|---|---|---|
| 실패 검출률 | 허용 시간 내 감지한 실패 시퀀스 비율 | 80% 이상 ⚠️ |
| 감지 지연 | 감지 시점 − 실제 실패 시작 시점 | 중앙값 120초 이내 ⚠️ |
| 정상 출력 오경보율 | 정상 영상 1시간당 잘못된 경고 횟수 | 0.5회 이하 ⚠️ |
| 딥러닝 추가 효과 | Baseline B와 A의 성능 비교 | 개선 여부 확인 |
| G-code 추가 효과 | Proposed와 Baseline B의 성능 비교 | 개선 여부 확인 |

### Secondary KPI

- 이미지 수준 이상 감지 성능(AUROC 등)
- 정답 영역이 있는 데이터의 이상 위치 탐지 성능
- 영상 처리속도(FPS) 및 추론 지연
- 적층 단계에 따른 오경보율
- 출력 형상이 달라졌을 때의 성능 변화

단일 이미지 수준의 AUROC가 높더라도 실제 실패를 늦게 감지하면 고객 가치가 낮을 수 있으므로, **실패 시점과 오경보율을 핵심 지표로 유지**한다.

## Q19. 성공한다면 어떻게 확장할 수 있나요?

**단기:** 정상 출력 및 서포트 실패 데이터를 확대하고, 다양한 프린터·슬라이서 환경에서 정상 특징 비교 방식을 검증한다.

**중기:** 여러 방향의 카메라를 활용해 가려진 서포트 영역을 관찰하고, G-code에서 복원한 예상 형상과 실제 영상의 정밀 비교를 연구한다.

**장기:** 충분한 신뢰성 검증 후 프린터 제어 시스템과 연동하여 출력 일시정지 및 사용자 확인 기능을 도입한다.

자동 제어 기능은 오경보에 따른 출력 품질 영향과 장비별 안전성을 별도로 검증해야 한다.

# Part 5. 기술 FAQ

## Q21. 왜 딥러닝이 필요한가요?

OpenCV의 프레임 차분과 Optical Flow는 움직임이나 변화량을 측정하는 데 유용하다.

그러나 정상 출력도 시간이 지날수록 형상이 변하고, Tree Support와 같은 구조는 복잡한 시각적 특징을 가진다.

PrintStop은 사전학습 CNN으로 정상 적층 형상의 특징을 추출하고, 현재 영상의 특징이 정상 데이터와 얼마나 다른지 판단한다.

**딥러닝이 반드시 우수하다고 가정하는 것이 아니라, 전통적인 영상 처리 방법보다 복잡한 정상·이상 형상을 더 잘 구별하는지 실험으로 확인한다.**

## Q22. PatchCore는 실제로 무엇을 학습하나요?

PatchCore는 사전학습된 CNN에서 이미지의 지역적 특징을 추출하고, 정상 이미지의 대표적인 특징을 Memory Bank에 저장한다.[^3]

새로운 영상에서는 해당 특징과 가장 가까운 정상 특징 사이의 거리를 이용해 이상 점수를 계산한다.

따라서 원본 이미지를 단순히 비교하는 것이 아니라, **딥러닝이 추출한 특징 공간에서 정상 상태와의 차이를 계산**한다.

단, 일반적인 PatchCore는 CNN 전체를 새로 학습하는 방식이 아니다. 사전학습된 특징 추출기를 활용해 정상 특징 저장소를 구성하는 방법이다.

## Q23. 정상 출력도 계속 모양이 바뀌는데, PatchCore를 그대로 써도 되나요?

그대로 적용하면 문제가 생길 수 있다.

예를 들어 10번째 레이어의 정상 서포트와 100번째 레이어의 정상 서포트는 형상이 크게 다를 수 있다.

따라서 PrintStop은 G-code의 적층 정보를 활용해 정상 이미지를 출력 단계별로 분류하거나, 유사한 공정 단계에서 추출한 특징끼리 비교하는 방법을 검증한다.

단순한 이미지 이상탐지에서 나아가 **적층 단계의 맥락을 고려하는 이상탐지**가 프로젝트의 핵심 연구 방향이다.

## Q24. G-code는 딥러닝 모델에 어떻게 연결하나요?

초기에는 G-code를 이미지와 함께 하나의 신경망에 입력하는 복잡한 멀티모달 구조를 사용하지 않는다.

대신 G-code에서 추출한 레이어와 출력 유형 정보로 현재 검사 영역이나 비교할 정상 특징 집합을 선택한다.

```text
G-code
  → 현재 적층 단계·서포트 영역
  → 검사 영역 및 정상 특징 선택
                           ↓
실제 영상 → CNN 특징 추출 → PatchCore 이상 점수
                           ↓
                    이상 Heatmap
                           ↓
                   시계열 판단
```

이 구조는 G-code 정보의 추가 효과를 별도 실험으로 분석할 수 있다는 장점이 있다.

## Q25. 베드 이탈과 서포트 파손은 같은 모델로 검출하나요?

초기에는 공통된 CNN 특징 추출 구조를 사용하되, 두 실패 유형의 평가를 구분한다.

베드 이탈은 출력물의 전체적인 움직임이 중요한 반면, 서포트 파손은 국소적인 형상 변화가 중요하다.

따라서 OpenCV 기반 움직임 분석과 딥러닝 이상 특징 분석이 각 실패 유형에서 어떤 장단점을 보이는지 별도로 평가한다.

하나의 모델이 모든 유형을 잘 검출한다고 전제하지 않는다.

## Q26. 왜 카메라를 한 대만 사용하나요?

카메라가 많아지면 관찰 가능한 영역은 넓어지지만, 시점 보정과 시간 동기화도 복잡해진다.

우선 고정 카메라 한 대에서 딥러닝 기반 이상탐지가 성립하는지를 검증하고, 가림 때문에 놓친 실패가 실제로 확인되면 추가 시점의 효과를 검토한다.

## Q27. VLM이나 AI 에이전트도 필요한가요?

필수는 아니다.

핵심 기능은 **CNN 특징 추출, 정상 상태 기반 이상탐지, G-code 정보 결합 및 시계열 판단**으로 구현한다.

VLM은 검출된 이상 영역을 설명하는 보조 기능으로 사용할 수 있지만, 실패 원인의 확정 판정에 사용하지 않는다.

AI 에이전트 역시 출력 이력 조회나 반복 실패 보고서 작성 등의 확장 기능에 적합하며, 초기 이상 판단에는 포함하지 않는다.

## Q28. 딥러닝 학습 데이터는 어디서 확보하나요?

정상 출력 이미지는 실제 프린터의 출력 과정을 촬영해 확보한다.

이때 여러 적층 단계와 형상을 포함하되, 특정 출력 작업의 연속 프레임이 학습과 평가에 동시에 사용되지 않도록 구분한다.

실제 서포트 파손 영상은 별도로 확보해야 한다.

공개된 `3DPrint-Failure-Video-Dataset`은 베드 접착 실패 검증에 활용할 수 있지만, 서포트 파손 성능의 근거로 사용할 수는 없다.[^4]

실제 파손 데이터가 부족할 경우 합성 이상 이미지는 알고리즘의 동작 점검에 사용할 수 있으나, 합성 데이터 결과만으로 실제 실패 검출 성능을 주장하지 않는다.

## Q29. GPU VRAM이 약 6GB여도 구현할 수 있나요?

PatchCore는 대규모 신경망을 처음부터 학습하는 방식이 아니므로, 경량 CNN과 제한된 입력 해상도를 활용하면 비교적 적은 GPU 자원으로 시작할 수 있다.

Anomalib의 PatchCore 구현을 활용해 사전학습 특징 추출과 정상 특징 저장 과정을 구성할 수 있다.[^5]

다만 처리속도와 메모리 사용량은 입력 해상도, CNN 크기, 정상 특징 개수에 따라 달라지므로 실제 환경에서 측정해야 한다.

초기 목표는 녹화 영상의 이상 분석이며, 실시간 추론 성능은 별도 평가한다.

## Q30. PrintStop이 해결하지 못하는 문제는 무엇인가요?

현재 시스템은 다음을 보장하지 않는다.

- 내부 응력이나 접착 강도의 직접 측정
- 실제 파손 이전의 미래 실패 예측
- 카메라에서 보이지 않는 내부 결함 검출
- 모든 서포트 형상과 필라멘트에 대한 범용 성능
- 영상만으로 결함의 정확한 물리적 원인 확정
- 검증되지 않은 자동 출력 중단의 안전성

PrintStop의 목표는 **실제로 관찰 가능한 이상을 딥러닝으로 분석하고, G-code와 연결하여 판단 근거를 제공하는 것**이다.

## B-1. 데이터 구성

| 구분 | 내용 | 용도 |
|---|---|---|

| 정상 출력 평가 데이터 | 학습과 다른 출력 작업 | 오경보 및 일반화 평가 |
| 베드 이탈 실패 데이터 | 정답 시작 시점이 있는 영상 | 초기 이상 감지 검증 |
| 서포트 실패 데이터 | 파손 시점과 영역이 확인된 영상 | 서포트 이상 검증 |
| G-code 연계 데이터 | 동일 출력의 영상과 G-code | 공정 정보 결합 효과 검증 |

## B-2. 핵심 평가 수식

```text
Detection Delay
= 감지 시점 - 실제 실패 시작 시점

False Alarms per Hour
= 정상 구간의 잘못된 경고 수 / 정상 영상 시간(h)

Event Recall
= 허용 시간 안에 감지한 실패 시퀀스 수
  / 전체 실패 시퀀스 수
```

또한 딥러닝을 통해 생성한 이상 Heatmap은 정답 영역 주석이 있는 데이터에서 별도로 평가한다.

출력 시퀀스 단위 데이터 분리와 동일 평가 조건을 유지하여 성능을 비교한다.

또한 기존 감지 서비스가 제공하지 못하는 기능이 고객에게 충분한 가치가 있는지 확인해야 한다.
