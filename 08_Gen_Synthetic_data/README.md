# 생성형 AI를 활용한 제조 결함 이미지 생성 및 조건별 성능 비교

## 1. 프로젝트 소개

이번 프로젝트에서는 Stable Diffusion과 AnomalyAny를 이용해 정상 제품 이미지에 인위적인 결함을 생성하는 실습을 진행하였다.

제조업에서는 다양한 불량 유형을 미리 확보하기 어렵고, 드물게 발생하는 결함은 학습에 필요한 데이터가 부족할 수 있다. 생성형 AI를 활용하면 이러한 문제를 보완할 수 있을 것으로 생각했다.

다만 실제로 사용하려면 결함처럼 보이는 이미지를 만드는 것만으로 충분하지 않다고 생각했다. 의도한 결함이 만들어졌는지, 결함이 없는 정상 영역은 얼마나 유지되었는지, 생성 조건에 따라 결과가 얼마나 달라지는지를 확인할 필요가 있었다.

이에 따라 수업에서 진행한 Stable Diffusion과 AnomalyAny 실습을 바탕으로 다섯 가지 추가 실험을 구성하였다.

## 2. 프로젝트 목표

첫 번째 목표는 Stable Diffusion의 이미지 생성 방식과 Inpainting의 차이를 이해하는 것이다.

두 번째 목표는 AnomalyAny를 활용해 정상 이미지에 균열과 같은 결함을 생성하고, 프롬프트와 입력 이미지가 생성 과정에 어떤 역할을 하는지 확인하는 것이다.

세 번째 목표는 마스크, 프롬프트, Seed, 제품 이미지, 입력 이미지 가이던스 조건을 변경하여 생성 결과를 비교하는 것이다.

마지막으로 생성 이미지와 원본 이미지의 차이를 정량적으로 분석하고, 실제 제조 결함 데이터로 활용하기 위해 어떤 검증이 필요한지 생각해보고자 하였다.

## 3. 수업 실습과 추가 실험

### 3.1 Stable Diffusion

8-1 실습에서는 텍스트 프롬프트를 입력해 이미지를 생성하고, 원본 이미지와 마스크를 이용하는 Inpainting도 실행하였다.

Text-to-Image에서는 이미지 전체를 생성하는 반면, Inpainting에서는 사용자가 지정한 영역의 내용을 변경할 수 있다는 차이가 있었다.

제조 결함 데이터를 생성하는 목적에서는 제품 전체를 새로 만드는 것보다 정상 제품의 구조를 유지하면서 필요한 결함만 추가하는 방식이 더 적합할 것으로 생각했다.

### 3.2 AnomalyAny

8-2 실습에서는 AnomalyAny의 공개 구현을 이용하여 정상 제품 이미지에 텍스트로 지정한 결함을 생성하였다.

수업에서 제공한 실습은 테이블의 변색, 헤이즐넛의 균열, PCB의 균열 등을 예시로 활용하였다.

이 과정에서 생성 이미지가 프롬프트뿐 아니라 입력 이미지, Attention을 적용할 토큰, 이미지 가이던스 설정에도 영향을 받는다는 점에 관심을 갖게 되었다.

### 3.3 개인 추가 실험

기존 실습에서는 결함 생성 과정을 확인하는 데 집중했다면, 추가 실험에서는 생성 조건을 변경했을 때 나타나는 차이를 확인하는 데 중점을 두었다.

비교 기준은 `E00_baseline`으로 정하고, 가능한 한 한 번에 하나의 조건만 변경하여 결과를 비교하도록 구성하였다.

## 4. 실험 환경

| 구분 | 사용 환경 및 설정 |
|---|---|
| 운영체제 | Windows |
| 실행 환경 | Conda, Jupyter Notebook |
| GPU | NVIDIA GeForce RTX 4050 Laptop GPU, VRAM 6GB |
| Python | 3.10 |
| PyTorch | 2.3.1+cu121 |
| Diffusers | 0.21.1 |
| Transformers | 4.29.2 |
| 기반 모델 | Stable Diffusion v1.5 |
| 사용 코드 | AnomalyAny 공개 구현 |
| 입력 이미지 | 512 × 512 |
| 기준 Seed | 2026 |
| Diffusion Steps | 120 |
| Guidance Scale | 12.5 |
| 기준 입력 이미지 가이던스 | 0.30 |

원본 AnomalyAny 실습은 200단계로 설정되어 있었으나, 이번에는 실행 시간을 고려하여 120단계로 변경하였다.

또한 GPU 메모리 부족 문제를 줄이기 위해 FP16 연산과 Attention 관련 메모리 최적화를 적용하였다.

Attention 손실 계산 중 자료형 문제를 일으킬 수 있는 부분도 수정하였다. 따라서 이번 결과는 원본 논문의 설정을 그대로 재현한 결과가 아니라, 개인 컴퓨터의 실행 환경에 맞게 조정한 실험 결과이다.

## 5. 데이터 및 실험 조건

기준 이미지로는 AnomalyAny에서 제공하는 헤이즐넛 정상 이미지를 사용하였다.

이와 별개로 새로운 제품 사진도 준비하였다. 원본 코드에서 사용한 제품 외에도 결함을 생성할 수 있는지 확인하기 위한 목적이다.

모든 실험의 기본 결함은 균열로 설정하였으며, 각 조건은 다음과 같이 구성하였다.

| 실험 | 변경한 조건 | 확인할 내용 |
|---|---|---|
| E00_baseline | 헤이즐넛, Seed 2026, 마스크 미적용 | 기본 생성 결과 |
| E01_mask_on | 마스크 적용 | 결함 발생 영역과 정상 영역의 변화 |
| E02_simple_prompt | 상세 프롬프트를 간단한 문장으로 변경 | 프롬프트 구체성의 영향 |
| E03_seed_plus1 | Seed 2027 | 생성 결과의 다양성 |
| E04_seed_plus2 | Seed 2028 | 생성 결과의 반복성 |
| E05_new_product | 새로운 제품 이미지 사용 | 다른 제품에 대한 적용 가능성 |
| E06_init_020 | 입력 이미지 가이던스 0.20 | 생성 결과와 원본의 차이 |
| E07_init_045 | 입력 이미지 가이던스 0.45 | 생성 결과와 원본의 차이 |

전체 실험은 기준 조건을 포함하여 8개 이미지 생성 조건으로 구성하였다.

프롬프트 비교에서는 주 프롬프트를 유지하고 상세 설명만 변경하였다. Seed 실험에서도 입력 이미지와 생성 조건을 유지해 무작위 초기값에 따른 차이를 확인할 수 있도록 하였다.

새로운 제품 실험은 입력 대상 자체가 달라지므로 다른 실험과 같은 기준으로 단순 비교하기 어렵다는 점을 고려하였다.

## 6. 생성 결과 평가 방법

생성 결과를 평가할 때는 원본 이미지와 생성 이미지의 픽셀 차이를 계산하였다.

먼저 균열이 나타나기를 기대하는 영역을 ROI로 지정하고, 해당 영역과 그 밖의 정상 영역을 구분하였다.

ROI는 직접 정한 비교 영역이며 실제 결함을 정밀하게 표시한 정답 마스크는 아니다.

| 지표 | 의미 |
|---|---|
| roi_mae | 결함 예상 영역에서 원본과 생성 이미지의 평균 차이 |
| outside_mae | ROI 외부 정상 영역의 평균 차이 |
| roi_changed_pct | ROI 내부에서 일정 수준 이상 변화한 픽셀의 비율 |
| outside_changed_pct | ROI 외부에서 일정 수준 이상 변화한 픽셀의 비율 |
| roi_share_pct | 전체 픽셀 변화 중 ROI 내부 변화가 차지하는 비율 |
| seconds | 이미지 생성에 걸린 시간 |

ROI 내부의 변화량이 크다는 것은 해당 영역이 많이 변경되었다는 의미이지, 결함이 자연스럽게 생성되었다는 의미는 아니다.

반대로 ROI 외부의 변화량이 작다면 원래 제품의 모습이 상대적으로 잘 보존되었다고 해석할 수 있지만, 이것만으로 전체 이미지의 품질을 판단할 수는 없다.

따라서 정량 평가와 별개로 생성 이미지를 직접 확인하고, 요청한 결함이 적절하게 표현되었는지와 원래 제품 구조가 유지되었는지를 각각 평가하도록 구성하였다.

## 7. 실험 진행 상태와 결과

추가 실험 노트북에는 8개 조건에 대한 실행 코드와 평가 코드가 구성되어 있다.

현재 확인된 저장 노트북에서는 모델 로드와 입력 이미지 확인, 메모리 최적화까지 완료되었다. 새로운 제품 이미지도 정상적으로 연결되었다.

기준 실험인 `E00_baseline`은 실행 중인 기록이 남아 있으며, 업로드된 파일에서는 120단계 중 29단계까지 확인된다.

따라서 현시점에서는 최종 생성 품질이나 8개 조건의 성능 차이를 확정하지 않았다.

실험 완료 후에는 `results/metrics.csv`와 `results/comparison_all.png`를 기준으로 수치를 정리하고, 생성 이미지에서 실제로 관찰한 차이를 함께 기록할 예정이다.

### 7.1 마스크 적용 결과

마스크를 사용했을 때 ROI 외부 변화량이 줄어드는지 확인한다. 결함 영역만 변경되었는지와 실제 균열의 표현이 자연스러운지는 별도로 평가한다.

### 7.2 프롬프트 비교 결과

간단한 프롬프트와 상세 프롬프트를 비교하여 원하는 균열 표현이 얼마나 달라지는지 확인한다.

### 7.3 Seed 변경 결과

동일한 입력 조건에서 Seed를 변경했을 때 균열의 형태와 위치가 얼마나 달라지는지 확인한다.

### 7.4 추가 제품 이미지 결과

헤이즐넛 외에 준비한 제품 사진에서도 원래 형상을 유지하면서 결함이 생성되는지 확인한다.

### 7.5 이미지 가이던스 결과

입력 이미지 가이던스를 0.20, 0.30, 0.45로 변경해 원본 보존과 결함 생성 변화량 사이의 관계를 비교한다.

## 8. 기존 실습에서 추가한 부분

이번 프로젝트에서는 GPU 메모리 제한으로 인해 발생하는 실행 문제를 해결하기 위해 FP16과 Attention 연산을 조정하였다.

또한 실험 조건과 Seed, 생성 시간 등을 기록하고, 동일한 조건에서 생성이 완료된 이미지가 있으면 재사용하도록 구성하였다.

원본 이미지와 생성 이미지를 비교하는 정량 평가 코드를 추가하였으며, ROI 내부와 외부를 구분해 분석할 수 있도록 하였다.

이를 통해 결함을 생성하는 과정뿐 아니라 생성 조건을 어떻게 설정하고 평가할 것인지까지 공부해보고자 하였다.

## 9. 개인 회고

### Keep

기준 조건을 먼저 정하고 다른 변수를 하나씩 변경하도록 실험을 구성한 점은 유지하고 싶다.

또한 생성 이미지의 품질을 눈으로만 판단하지 않고, 원본 이미지와 비교할 수 있는 지표를 마련한 점도 의미 있었다.

생성 조건과 결과를 파일로 저장하도록 구성한 덕분에 실행을 중단하더라도 이미 완료된 결과를 다시 활용할 수 있게 한 점이 좋았다.

### Problem

가장 어려웠던 점은 GPU 메모리와 생성 시간이었다.

Stable Diffusion 기반 생성 과정에 추가적인 Attention 최적화가 포함되어 있어 일반적인 이미지 생성 실습보다 계산 부담이 컸다.

또한 결함 영역의 변화량이 높다는 이유만으로 좋은 결함이라고 판단하기 어렵다는 문제도 있었다.

현재 설정에서는 모든 조건의 생성 결과를 확보하지 못했으므로 실제 결과를 바탕으로 한 비교와 결론은 추가로 작성해야 한다.

### Try

우선 계획한 8개 조건을 끝까지 실행하고, 실험마다 생성 이미지의 실제 변화와 정량 지표를 함께 확인하고자 한다.

특히 마스크를 적용했을 때 정상 영역 보존이 개선되는지, Seed를 변경해도 원하는 균열 표현이 유지되는지 확인해보고 싶다.

시간이 허용된다면 서로 다른 정상 이미지와 결함 프롬프트를 추가하여 특정 입력에만 잘 작동하는 것은 아닌지도 확인하고자 한다.

## 10. Action After Review

첫 번째로, 8개 조건의 생성 결과를 정리하고 ROI 내부 변화량과 정상 영역 변화량을 비교한다.

두 번째로, 각 생성 이미지를 직접 평가하여 결함 표현 정도와 원본 보존 정도를 1점에서 5점까지 기록한다.

세 번째로, 생성 결과가 좋은 조건과 좋지 않은 조건의 원인을 프롬프트, 마스크, Seed 및 가이던스 설정과 연결해 분석한다.

추가로 실제 결함 이미지만 사용해 학습한 탐지 모델과 합성 결함 데이터를 추가해 학습한 탐지 모델을 비교해보고 싶다.

이후 동일한 실제 테스트 데이터에서 AUROC, Recall, F1 등을 비교하면 생성 이미지가 실제 결함 검출 성능 향상에 도움이 되는지 평가할 수 있을 것이다.

이번 과제에서는 아직 결함 검출 모델의 성능 향상까지 검증한 것은 아니므로 후속 연구 방향으로 남겨두었다.

## 11. 실행 및 제출 파일
