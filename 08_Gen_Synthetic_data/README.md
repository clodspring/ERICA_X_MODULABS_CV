# 생성형 AI를 활용한 제조 결함 데이터 생성 프로젝트
## AnomalyAny 기반 추가 실험 및 결과 검토

컴퓨터 비전 수업에서 Stable Diffusion과 AnomalyAny를 활용해 정상 제품 이미지에 결함을 생성하는 실습을 진행했다. 이번 프로젝트에서는 제공된 코드를 다시 실행하는 것에 그치지 않고, 생성된 이미지가 실제로 어떤 특성을 보이는지 직접 확인하고 싶었다. 그래서 결함이 원하는 위치와 형태로 만들어지는지, 그리고 결함을 생성하는 동안 정상 제품의 형상이 얼마나 유지되는지를 비교하는 추가 실험을 계획했다.

이번 프로젝트에서 가장 중요하게 본 점은 "생성되었다"와 "쓸 수 있는 데이터가 생성되었다"는 같지 않다는 것이다. 실제로 실행 과정에서는 dtype 오류, 메모리 부족, NaN 발생, 검은 이미지 출력 같은 문제를 겪었고, 이를 하나씩 수정하면서 최종적으로 기준 실험 이미지를 생성하고 결과를 분석했다.

## 1. 프로젝트 목표

- 생성형 AI를 이용해 정상 제품 이미지에 결함을 만드는 과정을 이해한다.
- 결함 생성 결과가 실제로 자연스러운지, 그리고 원본 제품 형상이 유지되는지를 함께 평가한다.
- 조건을 하나씩 바꾸는 비교 실험을 설계해 결과 차이를 해석한다.
- 단순한 실행 성공이 아니라, 실제 제조 데이터로 활용 가능한지 비판적으로 검토한다.

## 2. 수업 실습에서 이해한 내용

AnomalyAny는 사전학습된 확산 모델을 이용해 정상 이미지에 텍스트로 지정한 이상 상태를 만들어 내는 방식이다. 일반적인 이미지 생성과 달리, 제품의 원래 형상을 어느 정도 유지하면서 특정 결함을 표현해야 한다는 점이 중요하다.

수업에서는 제조업에서 실제 불량 데이터가 부족한 상황을 가정하고, 합성 결함 이미지를 통해 데이터 증강이나 새로운 결함 유형 생성을 시도할 수 있다고 설명했다. 나는 여기서 한 걸음 더 나아가, 생성된 결과가 실제로 믿을 만한지 스스로 검토해 보고 싶었다.

내가 추가로 궁금했던 점은 다음과 같았다.

- 결함 영역을 마스크로 지정하면 정상 영역 변화가 줄어드는가
- 프롬프트 설명을 더 자세히 쓰면 결과가 좋아지는가
- Seed가 바뀌면 어떤 정도로 다른 결함이 생성되는가
- 다른 제품 이미지에도 적용할 수 있는가
- 입력 이미지 가이던스를 조절하면 원본 보존과 결함 생성이 어떻게 달라지는가

## 3. 실험 환경

| 항목 | 내용 |
|---|---|
| 기반 코드 | AnomalyAny 공식 GitHub |
| 생성 모델 | Stable Diffusion v1.5 계열 |
| 실행 환경 | Windows, Conda, Jupyter Notebook, NVIDIA RTX 4050 Laptop GPU |
| 주요 라이브러리 | Python 3.10, PyTorch 2.3.1+cu121, diffusers 0.21.1, transformers 4.29.2 |
| 입력 크기 | 512 × 512 |
| 기준 Seed | 2026 |
| 기준 입력 이미지 | AnomalyAny 저장소의 Hazelnut 정상 이미지 |
| 추가 입력 이미지 | `inputs/new_product.jpg` |
| 기준 입력 가이던스 | 0.30 |

실행 과정에서는 환경 차이로 인해 원본 실습 코드를 그대로 사용하는 데 한계가 있었다. 따라서 dtype 충돌 방지, prompt update 안정화, NaN 확인, 일부 실행 안전장치 등을 적용했다. 따라서 이번 결과는 논문 성능 재현이 아니라, 수업 실습을 바탕으로 한 추가 검토 결과라고 보는 편이 적절하다.

## 4. 내가 설계한 다섯 가지 추가 실험

기준 조건은 `E00_baseline`이다. 이후에는 가능하면 한 번에 하나의 조건만 바꾸어 결과를 비교하려고 했다.

| 구분 | 실험 ID | 변경한 조건 | 확인하려는 내용 |
|---|---|---|---|
| 기준 | E00_baseline | Hazelnut, Seed 2026, 마스크 없음, 가이던스 0.30 | 다른 실험의 기준 |
| 1. 마스크 | E01_mask_on | 기준 조건에서 마스크 적용 | 정상 영역 보존과 변화 위치 |
| 2. 프롬프트 | E02_simple_prompt | 간단한 설명으로 변경 | 설명 구체성의 영향 |

| 4. 새 제품 | E05_new_product | 다른 정상 제품 사진 사용 | 다른 대상에 대한 적용 가능성 |
| 5. 이미지 가이던스 | E06_init_020, E07_init_045 | 가이던스 0.20, 0.45 | 원본 보존과 생성 변화량 관계 |

## 5. 실행 과정에서 직접 수정한 점

이번 프로젝트는 단순히 제공된 코드를 재실행한 것이 아니라, 실제로 동작하게 만들기 위해 다음과 같은 수정과 점검을 진행했다.

- Conda 환경을 새로 구성하고 필요한 패키지 버전을 맞춤
- AnomalyAny 원본 소스 경로를 Notebook에서 자동으로 확인하도록 수정
- 새 제품 이미지 탐색 경로를 보완
- dtype 충돌을 줄이기 위해 실행 방식을 조정
- prompt update 단계에서 NaN이 발생하는 문제를 완화하기 위해 안전 우회 로직 적용
- 실행 결과가 검은 화면으로 나오는 경우를 확인하고, 수치 진단 셀을 추가해 원인을 점검
- 생성 후에는 원본 대비 ROI / ROI 외부 변화량을 계산하고 시각화하도록 구성

이 과정은 단순한 코드 실행보다 시간이 더 걸렸지만, 오히려 모델을 비판적으로 다루는 데 의미가 있었다고 생각한다.

## 6. 평가 방법

원본 이미지와 생성 이미지를 같은 크기로 맞춘 뒤, 예상 결함 영역인 ROI 내부와 바깥 영역의 차이를 계산했다. 여기서 ROI는 실제 정답 마스크가 아니라 실험자가 지정한 결함 후보 영역이다.

| 지표 | 의미 |
|---|---|
| `roi_mae` | ROI 내부 평균 픽셀 차이 |
| `outside_mae` | ROI 외부 평균 픽셀 차이 |
| `roi_changed_pct` | ROI 내부에서 변화량이 기준 이상인 픽셀 비율 |
| `outside_changed_pct` | ROI 외부에서 변화량이 기준 이상인 픽셀 비율 |
| `roi_share_pct` | 전체 변화량 중 ROI에서 발생한 비율 |
| `seconds` | 이미지 생성 시간 |

자동 지표만으로는 결함의 현실성을 완전히 판단할 수 없다고 생각했기 때문에, 생성 결과를 직접 보고 수동 평가도 함께 기록했다.

수동 평가는 다음 세 가지 기준으로 진행했다.

- `defect_fidelity_1to5`: 요청한 결함이 얼마나 잘 표현되었는가
- `product_preservation_1to5`: 원래 제품 형상이 얼마나 유지되었는가
- `comments`: 이미지에서 직접 관찰한 내용

### 결과 해석

기준 실험은 실행과 저장까지 성공했지만, 생성 결과를 보면 결함이 국소적으로 자연스럽게 표현되기보다는 전체적인 질감 왜곡이 강하게 나타났다. 정량 결과에서도 ROI 내부 변화량이 크긴 했지만, ROI 외부 변화도 무시하기 어려운 수준이었다.

즉, 이번 결과는 "모델이 이미지를 생성했다"는 점은 보여 주지만, "실제 제조 결함 데이터로 바로 사용할 수 있을 정도의 품질"이라고 보기는 어렵다고 판단했다.

## 8. 내가 느낀 점과 코드에 남긴 생각

이번 Notebook에는 단순 실행 코드만 넣지 않고, 각 단계마다 왜 그 셀을 실행하는지와 무엇을 확인하려는지 Markdown 셀과 주석으로 함께 남겼다.

특히 다음과 같은 생각을 코드와 Markdown에 반영했다.

- 생성 모델 실험에서는 실행 환경 정리도 중요한 작업이다.
- 비교 실험은 기준 조건을 정한 뒤 한 번에 하나의 변수만 바꾸는 것이 해석에 유리하다.
- 자동 지표는 유용하지만 결함 품질을 완전히 설명하지는 못한다.
- 실제 이미지를 보고 사람이 해석하는 과정이 꼭 필요하다.

## 9. Keep - Problem - Try

### Keep
- 기준 조건을 먼저 만들고 이후 조건을 하나씩 바꾸는 실험 구조는 유지하고 싶다.
- 자동 지표와 시각화, 수동 평가를 함께 사용하는 방식도 계속 활용하고 싶다.

### Problem
- RTX 4050 환경에서는 실행 시간이 길고, dtype 문제나 NaN 문제가 자주 발생했다.
- 생성된 결과가 항상 자연스러운 결함으로 이어지지 않았고, 정상 영역까지 크게 변형되는 문제가 있었다.

### Try
- 다음에는 `E01_mask_on`을 먼저 추가로 실행해서 정상 영역 보존이 실제로 개선되는지 확인하고 싶다.
- `E02_simple_prompt`와 비교해 프롬프트 구체성이 결과에 미치는 영향도 보고 싶다.

## 10. Action After Review

다음에는 생성 성공 여부만 보지 않고, 생성된 결과가 실제로 사용할 만한 데이터인지 먼저 확인하려고 한다. 이후에는 단순히 이미지가 그럴듯해 보이는 수준을 넘어서, 합성 결함 이미지를 실제 결함 검출 모델 학습에 추가했을 때 성능 향상이 있는지도 검증해 보고 싶다.

예를 들어 실제 데이터만 학습한 모델과, 실제 데이터에 합성 결함 이미지를 추가한 모델을 같은 테스트셋에서 비교해 AUROC, Recall, F1-score 등을 확인하면 합성 데이터의 실제 활용 가능성을 더 분명히 판단할 수 있을 것이다.
